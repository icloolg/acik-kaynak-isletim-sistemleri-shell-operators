01 Giriş

test Komutu Nedir?

test komutu, bir koşulun doğru mu yanlış mı olduğunu çıkış kodu (exit status) ile bildiren özel bir kabuk komutudur. Ekrana hiçbir şey yazdırmaz — sadece 0 (başarılı/doğru) veya 1 (başarısız/yanlış) döndürür. Bu çıkış kodu if gibi yapılarla birleştirilerek karar mekanizmaları oluşturulur.

ÇIKIŞ KODU
$?
Son komutun sonucunu tutan özel değişken. 0 = başarı, 1 = hata.
SAYISAL
-eq -gt
Sayıları karşılaştır: eşit mi, büyük mü, küçük mü?
STRING
= -z -n
Metin karşılaştır: eşit mi, boş mu, dolu mu?
DOSYA
-f -d -r
Dosya/dizin var mı? Okunabilir mi? Çalıştırılabilir mi?
🎙 Temel Mantık

test komutu sessizdir: ekrana bir şey yazmaz. Sonucunu echo $? ile ya da doğrudan if bloğuyla okursunuz. 0 döndürmesi "koşul doğru", 1 döndürmesi "koşul yanlış" anlamına gelir.

💡 [ ] Kısayolu

test $a -eq $b ile [ $a -eq $b ] tamamen aynıdır. Köşeli parantez test'in sözdizimsel kısaltmasıdır. Bash scriptlerinde [ ] kullanımı daha yaygındır.

🎓 Ders Anlatımı — Neden test Komutuna İhtiyaç Var?
›
1

Her komut bir çıkış kodu döndürür

Linux'ta çalışan her program bittiğinde işletim sistemine bir sayı bırakır. Bu sayı 0 ise başarılı, 0'dan farklıysa hata anlamına gelir. Bu evrensel kural tüm Unix araçlarında geçerlidir. $? değişkeni her zaman bir önceki komutun bu sonucunu tutar.

2

test komutu bu kodu üretmek için özelleşmiştir

Diğer komutlar kendi işlerini yaparken tesadüfen çıkış kodu üretir. test ise yalnızca koşul değerlendirmek için tasarlanmıştır: sayı karşılaştırır, string sınar, dosya varlığını kontrol eder. Çıktı üretmez, sadece kodu döndürür.

3

if ile birleşince karar mekanizması oluşur

Shell programlamanın kalbi budur: if deyimi bir komutun çıkış koduna bakar. Eğer 0 ise then bloğunu, değilse else bloğunu çalıştırır. test bu kodu üretir, if bunu tüketir.

02 Sayısal Operatörler

Sayıları Karşılaştırmak

test komutu sayısal karşılaştırma için özel bayraklar kullanır. Matematikteki > ve < sembolleri shell'de yönlendirme operatörü olduğundan sayısal karşılaştırmada kullanılamaz — bunun yerine sözcük kısaltmaları kullanılır.

OperatörAnlamıÖrnek
-eqEşit (equal)test $a -eq $b
-neEşit değil (not equal)test $a -ne $b
-gtBüyüktür (greater than)test $a -gt $b
-ltKüçüktür (less than)test $a -lt $b
-geBüyük veya eşit (≥)test $a -ge $b
-leKüçük veya eşit (≤)test $a -le $b
Basit $? ile çıkış kodu okuma
~1 dk ›

Slayttaki örneği adım adım inceleyelim. a=12, b=23 olduğundan 12 eşit 23 yanlıştır → test 1 döndürür.

bash
$> a=12; b=23
$> test $a -eq $b # 12 == 23? → yanlış
$> echo $?
1 ← 1 = koşul yanlış (başarısız)

$> test $a -lt $b # 12 < 23? → doğru
$> echo $?
0 ← 0 = koşul doğru (başarılı)

$> [ $a -gt $b ] # köşeli parantez = test kısayolu
$> echo $?
1 ← 12 > 23 yanlış
$ a=12; b=23 $ test $a -eq $b # 12 eşit 23? $ echo $? 1 ← YANLIŞ (eşit değil) $ test $a -lt $b # 12 küçük 23? $ echo $? 0 ← DOĞRU (12 gerçekten 23'ten küçük) $ [ $a -gt $b ] # 12 büyük 23? $ echo $? 1 ← YANLIŞ
Orta Script: Sayı karşılaştırma — not hesaplama
~2 dk ›

Bir öğrencinin notunu okuyup geçti/kaldı kontrolü yapan script:

not_kontrol.sh bash script
#!/bin/bash
echo -n "Notunuzu girin: "
read not

if [ $not -ge 50 ]; then
echo "✓ Geçtiniz! Notunuz: $not"
elif [ $not -ge 40 ]; then
echo "⚠ Bütünleme hakkınız var (Not: $not)"
else
echo "✗ Kaldınız. Notunuz: $not"
fi
bash — çalıştırma
$> chmod +x not_kontrol.sh
$> ./not_kontrol.sh

🌐 Gerçek Hayat: Otomasyon Sistemleri

Üniversite not sistemleri, maaş bordrosu hesaplama, yaş kontrolü gibi tüm sayısal karar mekanizmaları bu kalıba dayanır. Örneğin bir sunucu izleme scripti CPU kullanımı 90'ı geçince uyarı gönderir: [ $cpu -gt 90 ]

$ ./not_kontrol.sh Notunuzu girin: 65 ✓ Geçtiniz! Notunuz: 65 $ ./not_kontrol.sh Notunuzu girin: 43 ⚠ Bütünleme hakkınız var (Not: 43) $ ./not_kontrol.sh Notunuzu girin: 28 ✗ Kaldınız. Notunuz: 28
Zor Script: CPU kullanımı izleme
~3 dk ›
cpu_izle.sh bash script
#!/bin/bash
ESIK=80 # uyarı eşiği %80
CPU=$(top -bn1 | grep "Cpu(s)" | awk '{print int($2)}')

if [ $CPU -ge $ESIK ]; then
echo "⚠ UYARI: CPU kullanımı %$CPU (eşik: %$ESIK)"
echo "$(date): CPU=$CPU%" >> /var/log/cpu_uyari.log
else
echo "✓ CPU normal: %$CPU"
fi
🌐 Gerçek Hayat: DevOps & SRE

Nagios, Zabbix, Prometheus gibi izleme araçlarının alarm mantığı tam olarak bu kalıba dayanır. Cron job ile her 5 dakikada çalıştırılırsa gerçek bir sunucu izleme sistemi elde edilir: */5 * * * * /opt/cpu_izle.sh

03 String Operatörleri

Metin Karşılaştırmak

Metin (string) karşılaştırmaları için test farklı operatörler kullanır. Sayısal operatörlerden ayrı tutmak önemlidir: metinler için = ve !=, sayılar için -eq ve -ne.

OperatörAnlamıÖrnek
=String eşitliğitest "$ad" = "Ahmet"
!=String eşitsizliğitest "$ad" != "Ali"
-zString boş mu? (zero length)test -z "$adres"
-nString dolu mu? (non-zero)test -n "$ad"
Basit Slayttaki örnekler — -z ve -n
~1 dk ›

Slayttaki örnekleri tek tek çalıştıralım ve neden o sonucu döndürdüğünü anlayalım:

bash
$> name="Ahmet"

$> test -z $name # "Ahmet" boş mu?
$> echo $?
1 ← Hayır, boş değil → koşul YANLIŞ → 1

$> test -n $name # "Ahmet" dolu mu?
$> echo $?
0 ← Evet, dolu → koşul DOĞRU → 0

$> test -z "$address" # address tanımsız → boş sayılır
$> echo $?
0 ← Evet, boş → koşul DOĞRU → 0

$> test $name = "Ali" # "Ahmet" == "Ali"?
$> echo $?
1 ← Hayır → koşul YANLIŞ → 1
⚠️ Tırnak İşareti Önemli

Değişkenleri her zaman tırnak içinde kullanın: test -z "$adres". Tırnaksız kullanımda değişken boşsa test -z argümansız kalır ve hata verir.

$ name="Ahmet" $ test -z $name # Ahmet boş mu? $ echo $? 1 ← Hayır (boş değil) → YANLIŞ $ test -n $name # Ahmet dolu mu? $ echo $? 0 ← Evet (dolu) → DOĞRU $ test -z "$address" # address tanımsız $ echo $? 0 ← Evet (boş) → DOĞRU $ test $name = "Ali" # Ahmet == Ali? $ echo $? 1 ← Hayır → YANLIŞ

giris_kontrol.sh bash script
#!/bin/bash
echo -n "Kullanıcı adı: "

04 Dosya Operatörleri

Dosya ve Dizin Kontrolü

Shell scriptlerinin en sık kullandığı test türü dosya kontrolüdür. Bir dosyayı işlemeden önce var olup olmadığını, okunabilir mi yazılabilir mi çalıştırılabilir mi olduğunu kontrol etmek iyi bir pratiktir.

OperatörAnlamıÖrnek
-fDosya var mı?test -f "mydoc.doc"
-sDosya var ve boyutu > 0?test -s "log.txt"
-dDizin var mı?test -d "$HOME"
-rDosya okunabilir mi?test -r "config.cfg"
-wDosya yazılabilir mi?test -w "veri.db"
-xDosya çalıştırılabilir mi?test -x "script.sh"
Basit Slayttaki dosya örnekleri

$> test -f "mydoc.doc"
$> echo $?
0 ← dosya var → DOĞRU

$> test -r "mydoc.doc" # okuma izni var mı?
$> echo $?
0 ← okuma izni var → DOĞRU

$> test -d "$HOME" # home dizini var mı?
$> echo $?
0 ← $HOME her zaman var → DOĞRU

$> test -x "mydoc.doc" # çalıştırılabilir mi?
$> echo $?
1 ← .doc çalıştırılamaz → YANLIŞ
$ test -f "mydoc.doc" $ echo $? 0 ← dosya mevcut → DOĞRU $ test -r "mydoc.doc" $ echo $? 0 ← okuma izni var → DOĞRU $ test -d "$HOME" $ echo $? 0 ← home dizini var → DOĞRU $ test -x "mydoc.doc" $ echo $? 1 ← çalıştırma izni yok → YANLIŞ

cat "$DOSYA"

05 Mantıksal Operatörler & if

Koşulları Birleştirmek ve if Yapısı

Birden fazla koşulu tek test içinde birleştirmek için mantıksal operatörler kullanılır. Bu operatörler, gerçek programlarda birçok koşulu tek seferde değerlendirmeyi sağlar.

OperatörAnlamıÖrnek
-aMantıksal VE (AND) — her ikisi de doğru olmalıtest -r dosya -a -w dosya
-oMantıksal VEYA (OR) — biri doğru olsa yetertest -f dosya -o -d dosya
!Mantıksal DEĞİL (NOT) — koşulu tersine çevirirtest ! -f dosya
Basit -a ile çoklu koşul — slayttaki örnek
~1 dk ›

Slayttaki örnek: bir dosyanın hem okunabilir hem yazılabilir olup olmadığını tek test ile kontrol etme.

bash
# Hem okuma hem yazma izni var mı?
$> test -r "mydoc.doc" -a -w "mydoc.doc"
$> echo $?
0 ← ikisi de var → DOĞRU

# Dosya YOK mu? (! ile ters çevir)
$> test ! -f "olmayan.txt"
$> echo $?
0 ← gerçekten yok → DOĞRU

# Dosya veya dizin mi? (-o ile)
$> test -f "/home" -o -d "/home"
$> echo $?
0 ← /home bir dizin → DOĞRU
$ test -r "mydoc.doc" -a -w "mydoc.doc" $ echo $? 0 ← hem okunabilir hem yazılabilir → DOĞRU $ test ! -f "olmayan.txt" $ echo $? 0 ← dosya gerçekten yok → DOĞRU $ test -f "/home" -o -d "/home" $ echo $? 0 ← /home bir dizin → DOĞRU
Orta Slayttaki if örneği — who | grep ile kullanıcı kontrolü
~2 dk ›

Slayttaki örnek: sisteme giriş yapmış kullanıcıları listeleyen who çıktısını grep ile filtrele. grep -s sessiz modda çalışır; sadece çıkış kodu döndürür.

kullanici_kontrol.sh bash script — slayttaki örnek
#!/bin/bash
if who | grep -s ahmet > /dev/null
then
echo "ahmet is logged in CE server"
else
echo "ahmet not available in CE server"
fi
🔍 Nasıl Çalışır?

who → sisteme giriş yapmış kullanıcıları listeler.
| grep -s ahmet → çıktı "ahmet" içeriyorsa 0, içermiyorsa 1 döndürür.
> /dev/null → grep çıktısı ekrana değil çöp kutusuna gider.
if → grep'in çıkış koduna bakar: 0 ise then, değilse else çalışır.

$ who ahmet pts/0 2024-01-15 09:23 iclal pts/1 2024-01-15 10:45 $ ./kullanici_kontrol.sh ahmet is logged in CE server --- ahmet çıkış yaptıktan sonra --- $ ./kullanici_kontrol.sh ahmet not available in CE server
Zor Script: Tam sistem kontrol scripti
~4 dk ›

Tüm operatör türlerini birleştiren kapsamlı bir sistem sağlık kontrol scripti:

sistem_saglik.sh bash script
#!/bin/bash
echo "=== Sistem Sağlık Kontrolü ==="

# 1. Disk kullanımı (sayısal)
DISK=$(df / | tail -1 | awk '{print int($5)}')
if [ $DISK -ge 90 ]; then
echo "✗ DİSK: %$DISK doluluk — KRİTİK!"
else
echo "✓ DİSK: %$DISK doluluk — Normal"
fi

# 2. Log dosyası (dosya + boyut)
if [ -f "/var/log/syslog" -a -s "/var/log/syslog" ]; then
echo "✓ SYSLOG: Mevcut ve dolu"
else
echo "⚠ SYSLOG: Bulunamadı veya boş"
fi

# 3. Root mu? (string)
if [ "$USER" = "root" ]; then
echo "⚠ Uyarı: root olarak çalışıyorsunuz!"
else
echo "✓ Kullanıcı: $USER"
fi

echo "=== Kontrol tamamlandı ==="
🌐 Gerçek Hayat: SysAdmin Araçları

Bu tür scriptler cron ile otomatikleştirilir. Büyük sistemlerde Ansible, Puppet gibi araçlar da benzer mantığa dayanır. Aynı script e-posta bildirimi eklenirse tam bir izleme aracına dönüşür.

=== Sistem Sağlık Kontrolü === ✓ DİSK: %43 doluluk — Normal ✓ SYSLOG: Mevcut ve dolu ✓ Kullanıcı: iclal === Kontrol tamamlandı ===
