01 Giriş

Bash'in Güçlü Yapı Taşları

Bu derste üç önemli konuyu ele alacağız: Dizi Değişkenleri (tek isim altında birden fazla değer saklamak), export (değişkenleri alt süreçlere kalıtmak) ve ( ) / { } yapıları (komutları gruplayarak çalıştırmak).

KONU 1
Diziler
Birden fazla değeri tek değişkende sakla. İndeks ile eriş.
KONU 2
export
Değişkeni child process'e taşı. Kalıtım zinciri oluştur.
KONU 3
( ) { }
Alt kabuk mu, mevcut kabuk mu? Gruplama farkını anla.
🎙 Ön Koşul

Temel değişken atama (x=10), echo ve komut satırı kullanımını bildiğiniz varsayılmaktadır.

⚠️ zsh Kullanıcıları Dikkat — macOS Varsayılanı

macOS'ta terminal açtığınızda zsh (Z Shell) çalışır. Bu ders bash davranışını anlatmaktadır. İkisi arasında dizi konusunda kritik farklar vardır:

Özellikbashzsh
İlk indeks01
${dizi[0]}İlk elemanBoş döner!
$diziSadece ilk elemanTüm diziyi döner

Örnekleri terminalde denemek için önce bash'e geçin:

$ bash

Hangi kabuğu kullandığınızı öğrenmek için: echo $SHELL → /usr/bin/zsh yazıyorsa zsh'desiniz.

🎓 Ders Anlatımı — Bu Derste Ne Yapacağız?
›
1

Neden dizi değişkeni kullanırız?

Tek bir değişkende birden fazla değer saklamak istediğimizde dizi kullanırız. Örneğin 5 öğrencinin notunu 5 ayrı değişkende tutmak yerine notlar=(85 90 72 95 88) şeklinde tek dizide tutabiliriz. Bu hem kodun okunmasını hem de yönetilmesini kolaylaştırır.

2

Neden indeks 0'dan başlar?

Bash ve pek çok programlama dili dizileri bellekte ardışık konumda saklar. İlk konumun adresi başlangıç noktasının tam kendisidir — yani 0 ofset. Bu, C dilinden gelen ve bilgisayar mimarisine dayanan bir gelenektir. zsh farklı bir tasarım tercihi yaparak 1'den başlatmıştır.

3

Neden export gerekir?

Linux'ta her süreç (process) kendi bellek alanında çalışır. Bir script çalıştırdığınızda yeni bir süreç doğar. Bu süreç, üst kabuğun değişkenlerini otomatik olarak görmez. export komutu değişkeni "ortam" (environment) katmanına taşır; bu katman tüm alt süreçlerle paylaşılır.

4

( ) ile { } neden farklı davranır?

Parantez () işletim sistemine yeni bir süreç açtırır — tıpkı yeni bir program başlatmak gibi. Süslü parantez {} ise yeni süreç açmaz, komutları doğrudan mevcut kabukta sırayla çalıştırır. Bu yüzden () içindeki değişiklikler dışarıya sızmaz, {} içindekiler sızar.

02 Dizi Değişkenleri

Dizi Tanımlama ve İndeks Erişimi

Dizi, tek bir değişken adı altında birden fazla değer saklayan yapıdır. Bash'te dizi boyutu önceden belirtilmez; dinamik olarak büyür. Elemanlar 0'dan başlayan indeksle erişilir.

💡 Temel Kural

$dizi yazmak ${dizi[0]} ile aynıdır — yani her zaman ilk elemanı döner!

⚠️ zsh'de Aynı Komutu Çalıştırırsanız

echo ${spor[0]} → zsh'de boş döner (zsh'de indeks 1'den başlar, 0. eleman yoktur)
echo $spor → zsh'de tüm diziyi döner (bash'de sadece ilk eleman döner)

Bu yüzden örnekleri denemeden önce terminale bash yazın.

🎓 Ders Anlatımı — Dizi Nasıl Çalışır?
›
1

declare -a ne işe yarar?

declare -a spor komutu bash'e "spor adında bir dizi değişkeni kullanacağım" der. Zorunlu değildir — doğrudan spor=(... ile de oluşturabilirsiniz — ama iyi bir alışkanlıktır. Kodu okuyan kişi değişkenin dizi olduğunu anında görür.

2

Parantez içi atama nasıl çalışır?

spor=(basketbol futbol tenis) yazınca bash boşlukları ayraç olarak kullanır ve her kelimeyi sırayla 0, 1, 2 indeksine atar. Dikkat: değerler tırnak içinde değilse boşluk içeren değerler yanlış bölünür.

3

spor[3]=hokey neden 4. eleman?

İndeks 0'dan başlar: 0→basketbol, 1→futbol, 2→tenis. Dolayısıyla 3. indeks 4. pozisyondur. Aradaki boşluklara (index 4, 5 gibi) ilerleyen atamalar yapılabilir; bash "seyrek dizi" (sparse array) destekler.

Basit Dizi tanımla ve elemanlara eriş
~1 dk ›

declare -a ile dizi oluşturulur, parantez içinde boşlukla ayrılmış değerler atanır.

bash
$> declare -a spor
$> spor=(basketbol futbol tenis)
$> spor[3]=hokey # 4. pozisyon (index 3)

$> echo ${spor[0]}
basketbol
$> echo ${spor[3]}
hokey
$> echo $spor # = ${spor[0]}
basketbol

İlk satırda declare -a ile dizi tanımlandı. Parantez içi toplu atama yapıldı. spor[3]=hokey ile 4. pozisyona yeni değer eklendi.

$ declare -a spor
$ spor=(basketbol futbol tenis)
$ spor[3]=hokey
$ echo ${spor[0]} → basketbol
$ echo ${spor[3]} → hokey
$ echo $spor → basketbol ← sadece ilk eleman!
Orta Var olan diziden yeni dizi oluştur
~2 dk ›

Bir dizinin içeriğini $dizi ile yeni diziye ekleyebilirsiniz. Ancak $dizi yalnızca ilk elemanı döndürdüğünden, tüm elemanlar için ${dizi[@]} kullanın.

bash
$> spor=(basketbol futbol)
$> ekstra=($spor tenis) # $spor → sadece basketbol
$> echo ${ekstra[*]}
basketbol tenis # futbol kayboldu!

$> dogru=(${spor[@]} tenis) # [@] tüm elemanları alır
$> echo ${dogru[*]}
basketbol futbol tenis # doğru sonuç
⚠️ Dikkat

Slayttaki moresports=($sports tennis) örneğinde futbol kaybolur çünkü $sports yalnızca ilk elemanı döndürür. Tüm elemanlar için ${sports[@]} kullanın.

$ spor=(basketbol futbol)
$ ekstra=($spor tenis)
$ echo ${ekstra[*]} → basketbol tenis ← futbol kayboldu!

$ dogru=(${spor[@]} tenis)
$ echo ${dogru[*]} → basketbol futbol tenis ✓
Zor Döngüyle dizi elemanlarını işle
~3 dk ›

Gerçek uygulamalarda diziler döngüyle işlenir. Aşağıdaki script not ortalaması hesaplar.

bash
$> declare -a notlar=(85 90 72 95 88)
$> toplam=0
$> for not in ${notlar[@]}; do
> toplam=$((toplam + not))
> done
$> sayi=${#notlar[@]}
$> echo "Ortalama: $((toplam / sayi))"
Ortalama: 86

$> echo "Eleman sayısı: ${#notlar[@]}"
Eleman sayısı: 5

${notlar[@]} tüm elemanları döner. ${#notlar[@]} eleman sayısını (5) verir.

🌐 Gerçek Hayat: Not Sistemleri

Üniversite otomasyon sistemleri, sınav notlarını dizide toplayıp ortalamasını hesaplamak için bu yapıyı kullanır. Apache log analizi, sunucu IP listesi işleme gibi görevler de aynı kalıba dayanır.

$ declare -a notlar=(85 90 72 95 88)
$ for not in ${notlar[@]}; do
> toplam=$((toplam + not))
> done
$ echo "Ortalama: $((toplam / sayi))"
Ortalama: 86
$ echo "Eleman sayısı: ${#notlar[@]}"
Eleman sayısı: 5

Zor Gerçek dünya: Sunucu listesi yönetimi
~3 dk ›

Sistem yöneticileri sunucu adreslerini dizi olarak saklar ve döngüyle ping atar.

bash
$> declare -a sunucular=("192.168.1.1" "192.168.1.2" "192.168.1.3")
$> echo "Toplam sunucu: ${#sunucular[@]}"
Toplam sunucu: 3

$> for ip in "${sunucular[@]}"; do
> ping -c1 "$ip" >/dev/null 2>&1
> if [ $? -eq 0 ]; then
> echo "$ip: ✓ çalışıyor"
> else
> echo "$ip: ✗ erişilemiyor"
> fi
$> done
192.168.1.1: ✓ çalışıyor
192.168.1.2: ✓ çalışıyor
192.168.1.3: ✗ erişilemiyor
🌐 Gerçek Hayat: DevOps & Ağ Yönetimi

Nagios, Zabbix gibi izleme araçlarının temelinde bu tür dizi+döngü yapıları yatar. Her sunucuya otomatik komut göndermek için Ansible de benzer mantık kullanır.

04 Export Değişkenleri

Değişkenleri Alt Süreçlere Kalıtmak

Bash'te tanımlanan değişkenler yalnızca o kabuğa aittir. Bir alt süreç (child process) çalıştırdığınızda, bu değişkenleri göremez. export komutu değişkeni "ortam değişkeni" haline getirir ve alt süreçlere kalıtır.

🎙 Günlük Hayat Örneği

Düşünün: Bir şirketin genel müdürü (parent shell) bilgileri çalışanlarla (child process) paylaşmak istiyor. Export olmadan bilgi paylaşılmaz; export ile bilgi kalıtılır.

Basit Export öncesi ve sonrası farkı
~1 dk ›

Slayttaki vartest script örneğini inceleyelim. Script iki değişkeni ekrana yazdırır.

bash (vartest içeriği)
#!/bin/bash
echo "x = $x"
echo "y = $y"
bash (terminal)
$> x=100 ; y=10
$> ./vartest
x = ← boş! export edilmedi
y = ← boş! export edilmedi

$> export y
$> ./vartest
x = ← hâlâ boş, export edilmedi
y = 10 ← artık görünür!

Yalnızca y export edildi. Bu yüzden vartest scripti y'yi görebiliyor, x'i göremiyorum.

=== Export öncesi ===
$ x=100 ; y=10
$ ./vartest
x = ← boş!
y = ← boş!

=== export y sonrası ===
$ export y
$ ./vartest
x = ← hâlâ boş
y = 10 ← görünür ✓

05 ( ) ve { } Yapıları

Subshell mi, Mevcut Kabuk mu?

Bash'te komutları gruplamak için iki yöntem vardır. Fark tek ama kritik: komutlar nerede çalışıyor?

Özellik( ) — Alt Kabuk{ } — Mevcut Kabuk
Çalıştığı yerYeni bir subshellMevcut shell
cd kalıcı mı?HayırEvet
Değişken sızar mı?HayırEvet
Arka plan (&)EvetEvet
I/O yönlendirmeEvetEvet
Sözdizim notuNormal boşlukSon emir sonrası ; veya newline zorunlu
Basit Değişken farkı: ( ) vs { }
~1 dk ›
bash
# ( ) → alt kabuk, x=100 dışarıya sızmaz
$> x=50; (x=100); echo $x
50 ← değişmedi!

# { } → mevcut kabuk, x=100 kalıcı olur
$> x=50; { x=100; }; echo $x
100 ← değişti!
--- Parantez (subshell) ---
$ x=50; (x=100); echo $x
50 ← alt kabuk dışarıya sızmaz

--- Süslü parantez (current shell) ---
$ x=50; { x=100; }; echo $x
100 ← mevcut kabukta kalıcı
Orta cd ve arka plan çalıştırma
~2 dk ›
bash
# ( ) → dizin değişmez
$> ( cd /tmp; ls; )
dosya1.txt dosya2.log
$> pwd
/home/kullanici ← hâlâ aynı dizin!

# { } → dizin değişir
$> { cd /tmp; ls; }
dosya1.txt dosya2.log
$> pwd
/tmp ← dizin değişti!

# Arka planda çalıştırma + hata yönlendirme
$> (prog1; prog2; prog3) 2>hata.txt &
[1] 12345 ← arka plan process ID
--- ( ) ile cd ---
$ ( cd /tmp; ls; )
dosya1.txt dosya2.log
$ pwd
/home/kullanici ← değişmedi

--- { } ile cd ---
$ { cd /tmp; ls; }
dosya1.txt dosya2.log
$ pwd
/tmp ← değişti!
Zor Paralel işlem ve hata yönetimi
~3 dk ›

Birden fazla işlemi paralel çalıştırmak ve çıktılarını birleştirmek için ( ) yapısı kullanılır.

bash
# Üç dizini paralel tara, tüm çıktıyı tek dosyaya
$> (
> find /home -name "*.log" 2>/dev/null
> find /var -name "*.log" 2>/dev/null
> find /tmp -name "*.log" 2>/dev/null
> ) > tum_loglar.txt

# { } ile mevcut kabukta değişken paylaş
$> {
> BASLA=$(date +%s)
> uzun_islem
> BITIS=$(date +%s)
> echo "Süre: $((BITIS-BASLA)) saniye"
> }
Süre: 4 saniye
🌐 Gerçek Hayat: CI/CD & Derleme Sistemleri

Jenkins ve GitLab CI pipeline'larında paralel derleme adımları tam olarak (cmd1; cmd2) & mantığıyla çalışır. Süreli işlemler için { } ile zaman ölçümü yaygın bir DevOps kalıbıdır.
